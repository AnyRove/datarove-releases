DataRove — настольный клиент баз данных со встроенным резервным копированием по расписанию и синхронизацией. Он работает на вашем компьютере (как приложение или фоновая служба), а телефон подключается к нему по локальной сети или через ретранслятор (relay). Соединение защищено сквозным шифрованием, а пароли от баз никогда не покидают компьютер.

**Базы данных:** MySQL · MariaDB · PostgreSQL · SQLite · SQL Server · MongoDB · Redis, с SSH-туннелями и TLS.

> **Статус:** 1.0.0. Установщики — на странице [Releases](../../releases); после установки приложения обновляются сами. Нажмите Watch, чтобы получать уведомления о новых версиях. Изменения — в [CHANGELOG](CHANGELOG.md).

## Возможности

### Просмотр и правка данных
- Быстрая таблица с виртуальной прокруткой, фильтрами, сортировкой и постраничным выводом. Правьте ячейки на месте или откройте строку целиком в форме, где у каждого типа столбца своё поле ввода (логическое, enum, дата, JSON, NULL / значение по умолчанию).
- Для внешнего ключа можно найти и выбрать строку в связанной таблице.
- Перед сохранением можно посмотреть точный SQL. Все изменения фиксируются одной транзакцией и при ошибке откатываются вместе. Удаление и подключения к продакшену требуют подтверждения.
- Копирование в CSV / TSV / JSON / SQL / Markdown, экспорт в файлы, импорт CSV / JSON.

![Таблица данных](docs/images/data.png)

### Запросы
- SQL-редактор с автодополнением по контексту: таблицы после `FROM` / `JOIN`, столбцы после `псевдоним.`, списки столбцов в `INSERT`, функции с сигнатурами, шаблоны запросов.
- При наведении на таблицу или столбец видны структура, типы и комментарии. Неверные имена таблиц, несуществующие `псевдоним.столбец` и `DELETE` / `UPDATE` без `WHERE` подчёркиваются ещё до запуска.
- Результат `SELECT` по одной таблице, включающий первичный ключ, можно править и сохранять прямо в результатах.
- Синтаксис оболочки MongoDB (`db.users.find({...})`) и командная строка Redis, обе с автодополнением.

![Редактор запросов](docs/images/query.png)

### Понять схему
- Базы → таблицы / представления / коллекции → столбцы, индексы, внешние ключи, триггеры, DDL, число строк и размер.
- ER-диаграмма, сравнение схем двух баз с генерацией SQL для миграции, обозреватель ключей Redis, монитор сервера (подключения, QPS, медленные запросы).

![ER-диаграмма](docs/images/er.png)

### Импорт и экспорт
- Экспорт таблицы или отфильтрованного результата в CSV, TSV, JSON, JSON Lines, SQL `INSERT` или Markdown; импорт CSV / TSV / JSON / JSON Lines (распознаются UTF-8 и GBK).
- Большие передачи идут в фоне на компьютере, с прогрессом и кнопкой отмены. Файлы передаются небольшими частями, поэтому после обрыва связи передача продолжается, а не начинается заново.
- Импорт выполняется в одной транзакции: если хотя бы одна строка не записалась, не записывается ничего, а проблемная строка указывается.

### Надёжные резервные копии
- Резервное копирование в файлы штатными утилитами (mysqldump / pg_dump / mongodump) или встроенным экспортом, сжатие gzip и шифрование AES-256-GCM, хранение последних N файлов или N дней.
- Каждый новый файл сразу после записи читается обратно и проверяется (контрольная сумма, расшифровка, разбор), так что повреждённый файл обнаружится в ту же ночь.
- Синхронизация с другой базой: полная замена, очистка и загрузка, добавление, upsert по первичному ключу или **инкрементальная** синхронизация по столбцу-метке (`updated_at`, автоинкрементный id…).
- Расписание: каждые N минут, ежедневно, еженедельно, ежемесячно или cron. Пропущенные запуски выполняются при старте. Уведомления на рабочем столе и через webhook. Любую копию можно восстановить в любое подключение одним щелчком.
- Синхронизация работает и между разными СУБД (например, PostgreSQL → MySQL). Каждая таблица записывается целиком или не меняется вовсе, а число строк сверяется перед фиксацией. Временные ошибки повторяются автоматически; если что-то всё ещё не прошло, **повторите только неудавшиеся части**. Недостающие утилиты (pg_dump и др.) ставятся из приложения в один клик.

![Резервные копии](docs/images/backups.png)

### Отмена ошибок
- На подключениях с пометкой «прод» DataRove сохраняет затронутые таблицы перед `UPDATE`, `DELETE`, `DROP`, `TRUNCATE`, правкой в таблице, импортом с перезаписью, синхронизацией или восстановлением.
- Отменить можно потом в один клик: возвращаются только отличающиеся строки, в одной транзакции. Снимки хранятся на компьютере в зашифрованном виде.

### Телефон — безопасно
- На телефоне тот же интерфейс. Для сопряжения достаточно отсканировать QR-код, учётная запись не нужна.
- У каждого телефона своя роль (только чтение, чтение и запись или администратор), её можно в любой момент изменить или отозвать. Временные права истекают сами, а журнал действий показывает, что делал каждый телефон.
- В той же сети Wi-Fi телефон подключается напрямую, вне её — через ретранслятор, который пересылает только шифротекст.

<p align="center"><img src="docs/images/phone-data.png" width="300" alt="DataRove на телефоне"></p>

### Компьютер
Работает из области уведомлений, запускается при входе в систему и умеет устанавливать себя как фоновую службу (launchd / systemd / Планировщик заданий Windows), чтобы резервное копирование шло и при закрытом окне. 10 тем, светлый и тёмный режим, 15 языков интерфейса.

## Безопасность вкратце

- Сохранённые пароли шифруются на компьютере локальным мастер-ключом. Интерфейс и сопряжённые телефоны видят только `••••`.
- Сопряжение по QR-коду использует 256-битный секрет, а короткий код, введённый вручную, усилен scrypt. Обе стороны проверяют ключи друг друга, поэтому ретранслятор не сможет подсунуть своё устройство.
- Каждый сеанс использует X25519 + ChaCha20-Poly1305 с новыми эфемерными ключами (прямая секретность). Подменённые, повторённые или переставленные кадры отклоняются, попытки понизить версию протокола — тоже.
- Публичный ретранслятор должен работать по `wss://`. Можно развернуть собственный ретранслятор или выполнять сопряжение только в локальной сети.
- Всё, что выходит за рамки самого DataRove, доступно только на компьютере: пути к утилитам, просмотр файлов, доступ к файлам SQLite и отправка сохранённого пароля на изменённый адрес.

О найденной уязвимости сообщайте по инструкции в [SECURITY.md](SECURITY.md).

## Установка

Скачайте файл для своей системы из [последнего выпуска](../../releases/latest). В каждом выпуске есть контрольные суммы SHA-256 в `SHA256SUMS.txt`. Установщики пока не подписаны сертификатом разработчика Apple или Microsoft, поэтому система один раз попросит подтверждение:

- **macOS**: откройте `.dmg` и перетащите DataRove в «Программы». Если при первом запуске macOS сообщает, что не может проверить приложение, откройте **Системные настройки → Конфиденциальность и безопасность**, прокрутите вниз и нажмите **Все равно открыть**. Если macOS сообщает, что приложение повреждено, выполните в Терминале `xattr -cr /Applications/DataRove.app` и откройте его снова.
- **Windows**: запустите `.exe`. Если появится SmartScreen, нажмите **Подробнее → Выполнить в любом случае**.
- **Linux**: сделайте `.AppImage` исполняемым и запустите его или установите `.deb`.
- **Android**: откройте `.apk` и разрешите установку из браузера или файлового менеджера. Приложение работает в паре с DataRove на компьютере или в прямом режиме само подключается к вашим базам данных (один раз активируйте телефон своей учётной записью DataRove).

Затем войдите в приложении по электронной почте и активируйте компьютер. DataRove бесплатен; платёжные данные не нужны.
